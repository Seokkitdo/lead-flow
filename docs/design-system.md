# LeadFlow 디자인 시스템

## 목적과 시각 원칙

직원이 고객 목록을 훑고 연락 결과를 빠르게 기록하는 업무 화면이다. 청록색 주요 액션, 짙은 네이비 탐색 영역, 밝은 중립색 작업 영역을 사용한다. 장식보다 상태·담당자·다음 행동을 우선한다. 직원 웹과 관리자 웹은 같은 토큰과 컴포넌트로 만든다.

## 단일 기준

`packages/ui/src/theme.css`가 색상·타이포그래피·간격·모서리·그림자·레이아웃의 기준이다. 기능 화면에서 색상을 직접 지정하지 않는다. 모든 상태는 색상과 한국어 텍스트를 함께 사용한다.

- 기본 본문 16px, 표·필드 보조 레이블 14px 이상, 부가 메타데이터 12px 이상.
- 간격은 4px 배수의 토큰으로 맞춘다. 화면마다 임의 간격 체계를 만들지 않는다.
- 주요 액션은 한 작업 영역에서 하나를 강조한다. 파괴적 작업은 위험 스타일과 확인을 사용한다.
- 버튼·입력에는 hover, disabled, focus-visible 상태를 갖춘다.
- 입력 오류는 필드 또는 작업 폼 가까이에 표시하고 입력값을 유지한다.

## 화면 패턴

- 데스크톱: 탐색 영역 → 요약/필터 → 고객 목록 → 독립된 고객 상세·업무 기록 페이지.
- 모바일: 필터와 목록은 한 열, 고객 상세는 전체 폭. 가로 스크롤은 데이터 표 영역에 한정.
- 목록에는 로딩, 오류와 재시도, 첫 고객 등록 안내, 검색 결과 없음, 페이지 이동이 존재한다.
- 저장 중에는 중복 제출을 막고 성공 시 관련 Query 캐시를 갱신한다.
- 재통화 상태는 일시 입력을 요구한다. 표시 시간대는 한국 시간이다.
- 외부에서 보낸 카카오톡은 '카카오톡 전달 기록'으로 표시한다.

## 공통 UI 확장 절차

1. 기존 `packages/ui`에 같은 역할의 컴포넌트/토큰이 있는지 확인한다.
2. 없다면 공통 패키지에 접근 가능한 primitive를 추가한다.
3. 웹·어드민에 같은 primitive를 적용한다.
4. 디자인 갤러리에서 일반·비활성·오류·상태 변형을 검토한다.
5. 자동 검사와 관련 사용자 흐름 테스트를 통과시킨다.

## 검증 하네스

- `pnpm check:design`: 앱과 공통 컴포넌트의 색상 리터럴·기본 팔레트·임의 색상·inline style 및 12px 미만 텍스트를 검사한다.
- `pnpm check`: Svelte/TypeScript 타입·접근성 진단 및 디자인 검사.
- `pnpm test:e2e`: 로그인·등록·배분·직원 업무 기록 등 사용자 여정을 실제 서버와 검증한다.
- `pnpm build`: 직원/관리자 배포 산출물 검증.
- `pnpm test:api`: 권한·원자성·중복·세션·이력 회귀 검증.
- GitHub Actions에서 같은 명령을 실행한다. 문서 규칙과 자동 검사를 함께 유지한다.

자동 색상 검사는 시각적 품질이나 전체 접근성을 보장하지 않는다. 신규 UI 패턴은 키보드 이동, 모바일 화면, 확대 시 표시를 함께 확인한다.

## 페이지 이동과 상태 변화

- 공통 탐색은 실제 링크를 사용한다. 기본 경로는 `/`, `/leads`, `/assignments`, `/team`, `/design-system`이다.
- 디자인 시스템 메뉴와 `/design-system` 페이지는 개발환경에서만 제공한다. 프로덕션 빌드에서는 메뉴를 숨기고 직접 접근도 제공하지 않는다.
- 고객 등록은 `/leads/new`, 상세는 `/leads/:id`, 상세 메뉴는 `/leads/:id/activity`, `/timeline`, `/assignment`, `/edit`이다. 직원 등록·계정 관리는 `/team/new`, `/team/:id`로 이동한다.
- 검색·필터·페이지 번호는 URL 쿼리에 보존한다. 상세 주소의 `from`은 목록으로 돌아갈 주소이며 동일 출처만 허용한다.
- 로그인은 `/login?next=...`에서 처리하고 성공하면 원래 페이지로 복귀한다. 인증 확인의 연결 오류는 로그인 실패와 구분해 재시도를 제공한다.
- 페이지 진입은 280ms, 버튼·메뉴 변화는 140ms, 알림·선택 영역은 200ms의 공통 모션 토큰을 사용한다. `prefers-reduced-motion`에서는 애니메이션을 제거한다.
- 이동 후 페이지 제목으로 키보드 포커스를 옮기고, 뒤로 가기에서는 이전 링크와 스크롤을 복원한다. 페이지 콘텐츠에는 모달 포커스 잠금을 적용하지 않는다.
- 조회 실패를 빈 데이터로 표시하지 않는다. 저장 실패는 입력을 유지하며 자동 재시도하지 않는다. 버전 충돌은 명시적으로 최신 내용을 불러온 후 다시 수정한다.
- 목록 갱신 중에는 고객 선택을 잠그고 행을 고객 ID로 고정한다. 저장 중에는 입력·중복 제출·페이지 이동을 잠근다.

## 상담 기록과 이력

`consultation-layout`은 업무 입력과 이전 상담·배분 이력을 데스크톱에서 나란히 표시하고 900px 이하에서는 한 열로 배치한다. 고객 상세 페이지의 URL·새로고침·이동 보호를 유지한다. 직원 목록은 최근 메모와 배분일을 보여주고 배분 후 미처리를 상담 상태와 구분한다. 로그인 화면과 메뉴는 접속 포트가 아닌 인증된 계정 권한을 기준으로 구성한다.

## 역할별 보조 페이지

직원 업무 상세 `/team/:id/work`, 재통화 일정 `/callbacks`, 내 계정 설정 `/account`, 업무 기록 상세 `/leads/:id/records/:recordId`를 제공한다. 기존 공통 패널·필드·버튼·오류·빈 상태를 사용한다. 재통화 기간과 직원 상세 필터·페이지는 URL에 보존하며 고객 상세의 `from`으로 복귀한다. 모바일 메뉴는 역할별 두 줄 배치로 모든 목적지를 노출한다. 계정·정정 폼에도 저장 중 이동 잠금, 미저장 확인, 충돌 복구를 적용한다.

## 상세 본문과 표 셀 링크

- 공통 `content-stack`은 패널 사이에 24px 간격을, `panel-content`는 본문에 데스크톱 24px·700px 이하 16px 여백을 제공한다. `panel` 단독 사용에는 본문 여백이 없다.
- `summary-grid`는 업무 수치를 3열로 표시하고 작은 화면에서는 1열로 전환한다. `filter-form`·`filter-fields`·`filter-actions`로 검색 조건과 실행 영역을 정렬한다.
- `TableCellLink`는 정보 셀의 여백까지 실제 링크의 클릭 영역으로 제공한다. 행의 주 링크에만 `primary`와 고유 ID를 지정해 키보드 탐색과 복귀 포커스를 유지한다. 보조 셀은 같은 주소를 사용하고 계정 관리처럼 목적지가 다른 작업은 별도 링크로 제공한다.
- 직원 상세는 기본 정보, 업무 요약, 담당 고객 검색·목록의 순서로 구성한다. 공통 패턴은 디자인 갤러리에서 확인한다.

등록 완료 안내와 업무 바로가기는 기존 panel·inline-actions 패턴을 사용한다. inline-actions·선택 작업 표시줄·직원 선택 항목은 작은 화면에서 줄바꿈하며, 버튼은 입력 영역의 높이에 맞춰 늘어나지 않는다.

## 사용자에게 표시하는 문구

화면·접근성 이름·API 오류 메시지에는 아래 용어를 사용한다. API 필드명과 저장된 기록은 별도 변경하지 않는다. 기존 기획 문서의 배분·유입·타임라인은 화면에서는 아래 표현으로 표시한다.

| 기존 표현           | 화면 표현              | 의미·작성 기준                                                                         |
| ------------------- | ---------------------- | -------------------------------------------------------------------------------------- |
| 고객 DB             | 고객 목록              | 고객을 찾고 등록하는 화면                                                              |
| 대시보드            | 업무 현황              | 현재 고객과 직원별 업무 수치                                                           |
| 배분                | 배정                   | 고객을 담당할 직원을 정함                                                              |
| 미배분              | 담당자 미지정          | 아직 담당자가 없음                                                                     |
| 배분 후 미처리      | 배정 후 기록 없음      | 현재 담당자가 이번 배정 이후 업무 기록을 저장하지 않음. 실제 연락 여부를 단정하지 않음 |
| 유입 경로·유입일    | 문의 경로·문의일       | 고객이 문의한 경로와 날짜. 시스템 등록일과 구분                                        |
| 최초 메모           | 등록 메모              | 등록 시 남긴 내용. 이후 업무 메모와 구분                                               |
| 타임라인            | 전체 기록              | 상담과 담당자 변경 기록                                                                |
| 현재 상태·업무 상태 | 상담 상태              | 고객의 진행 단계                                                                       |
| 기한 초과           | 예정 시간 지남         | 다시 연락하기로 한 시간이 지남                                                         |
| 비활성              | 이용 중지              | 로그인과 새 고객 배정을 막는 계정 상태                                                 |
| 로그인 세션 종료    | 모든 기기에서 로그아웃 | 비밀번호·계정 상태 변경의 영향                                                         |

- 버튼은 실제 동작을 쓴다. 직원 등록·변경 사항 저장·같은 번호로 새 고객 등록 등으로 구분한다. 선택만 하는 버튼은 저장이나 전송이 완료되는 것처럼 표현하지 않는다.
- 안내와 오류는 존댓말로 통일하고 다음 행동을 함께 설명한다. 불러오는 상태는 `불러오는 중…`, 완료는 `저장했습니다`로 구분한다.
- 요약 수치의 설명은 집계 기준을 쓴다. 연락·상담 진행 중에는 CONTACTING과 IN_PROGRESS가 모두 포함된다.
- 조회 실패, 검색 결과 없음, 아직 등록·배정된 고객 없음은 각각 다른 상황에 맞게 안내한다.
- 카카오톡 기록은 외부에서 직접 보낸 내용을 적는 기능이며, 전송 버튼으로 오해하지 않게 안내한다. 기록 정정·취소는 기존 기록과 상담 상태가 어떻게 유지되는지 설명한다.
