# 활동 이력 보존

활동은 추가만 가능하며 수정·삭제 API를 제공하지 않는다. 원래 작성자·시각·상태 전이를 보존한다.

잘못 기록한 활동은 기록 상세 화면에서 새 `MEMO` 활동으로 정정한다. `POST /api/leads/:leadId/activities/:activityId/corrections`는 현재 고객 접근 권한과 원본 소속을 확인한다. 메모에 원본 활동 ID, 정정/취소 사유와 정확한 내용을 남긴다. 현재 상태도 잘못 변경했다면 같은 요청의 `status`로 올바른 상태를 지정한다. 원본 활동과 정정 활동 모두 타임라인에 표시되며, 상태 수정과 정정 기록은 같은 트랜잭션으로 저장된다. 재통화 상태는 `callback_at`도 함께 지정해야 한다. 정정 요청에도 최신 `version`을 사용한다.

후속 단계에서는 `corrects_activity_id` 외래 키와 정정/취소 유형을 추가해 원본 연결 및 UI 표시를 구조화한다. 원본 행을 덮어쓰거나 삭제하는 방식으로 구현하지 않는다.

## 저장과 조회

모든 시각은 UTC로 저장한다. 유입일 필터의 날짜 경계와 대시보드의 오늘 기준은 Asia/Seoul이다. 고객 응답의 `last_activity_at`은 최신 업무 활동 시각이며 활동이 없으면 null이다. 담당자 배분 시각은 별도 `assigned_at`으로 유지한다. 목록은 현재 페이지의 활동 시각과 담당자 정보를 일괄 조회한다.

## PostgreSQL 회귀 테스트

`LEADFLOW_TEST_DATABASE_URL=postgresql+psycopg://... uv run pytest -q`로 동일 API 테스트를 실행한다. 테스트마다 임의의 전용 스키마를 생성하고 종료 시 해당 스키마만 제거한다. 테스트 DB 계정에는 스키마 생성 권한이 필요하다. 기본 실행은 메모리 SQLite다.
